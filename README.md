# xray-vps-setup

VLESS со своим доменом. А что еще нужно для счастья?

В данном варианте VLESS слушает на 443 и принимает все запросы, делая запрос на локальный Angie(форк nginx) только для сертификатов. В таком варианте задержка будет меньше, чем в варианте с Caddy/NGINX перед VLESS, где происходит множество лишних запросов.

## Скрипт

- Установит Xray/Marzban на ваш выбор. Для маскировки на корне домена отдаётся нейтральная страница входа (login-гейт в стиле self-hosted-панели), уникальная на каждом сервере (рандомизируется при установке) — создаёт впечатление приватного сервиса, доступного только после авторизации.
- На ваше усмотрение настроит:
- - Создаст пользователя для подключения, запретив вход от рута, добавит ему ключ для SSH и запретит вход по паролю. Вместе с этим шагом настраивается iptables (IPv4 и IPv6), запрещая все подключения, кроме SSH, 80 и 443.
- - Настроит WARP для ру-сайтов.

```bash
tmux
bash <(wget -qO- https://raw.githubusercontent.com/Akiyamov/xray-vps-setup/refs/heads/main/vps-setup.sh)
```

## Обход DPI и выбор сервера

По материалам разбора «сибирского» DPI (июнь 2026). Блокировка по VLESS/Reality срабатывает только при **одновременном** совпадении трёх сигналов (логика И), поэтому достаточно разорвать **любой** из них:

1. **Подсеть/ASN сервера** (Сигнал 1). Избегайте провайдеров, чьи диапазоны исторически режут: **Selectel, Yandex.Cloud, Hetzner, DigitalOcean, OVH**. Скрипт на установке сам предупредит, если ваш хостинг похож на один из них. Подсеть стоит проверить через [dpi-checkers](https://github.com/hyperion-cs/dpi-checkers) до того, как полагаться на сервер.
2. **TLS-фингерпринт** (Сигнал 2). Все клиентские конфиги и ссылка используют `fp=firefox` — это «лояльный» отпечаток, который и разрывает И-цепочку. **Не меняйте его** на `chrome`/`safari`/`randomized`. И **не меняйте фингерпринт под деградацией**: смена «на лету» эскалирует блок со 120 до 600 секунд на все TLS-соединения к узлу. Лояльный отпечаток должен стоять заранее.
3. **Поведение** (Сигнал 3). >3 параллельных коннектов с интервалом <350–400 мс к одному SNI за 60 с. У нас весь трафик идёт на один SNI (свой домен), а XTLS Vision глушит TCP-mux, поэтому это потенциально слабое место — сейчас оно гасится лояльным фингерпринтом (И-логика). Полная митигация потребовала бы XHTTP+XMUX (медленнее, хуже прячет форму TLS-в-TLS) или нескольких SNI — осознанно отложено.
