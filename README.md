# xray-vps-setup

VLESS со своим доменом. А что еще нужно для счастья?

Основной транспорт — **VLESS+gRPC+Reality**: gRPC мультиплексирует все потоки в один долгоживущий HTTP/2-коннект, поэтому клиент не выдаёт всплеск параллельных TLS-хендшейков — главный поведенческий маркер «сибирского» DPI (Сигнал 3, см. ниже). Рядом доступен вторичный **VLESS+Vision+Reality** на случай, если gRPC где-то деградирует.

Два Reality-инбаунда не могут делить один 443/TCP, поэтому на 443 стоит лёгкий SNI-роутер Angie (форк nginx): он по `ssl_preread` смотрит SNI **без терминации TLS** (Reality по-прежнему видит оригинальный ClientHello) и раздаёт соединения на локальные инбаунды — gRPC `127.0.0.1:8443`, Vision `127.0.0.1:8444`. Тот же Angie выпускает сертификаты и отдаёт нейтральную decoy-страницу на корне. Наружу открыты только 80/443; всё остальное — на localhost.

## Скрипт

- Установит Xray/Marzban на ваш выбор. Для маскировки на корне домена отдаётся нейтральная страница входа (login-гейт в стиле self-hosted-панели), уникальная на каждом сервере (рандомизируется при установке).
- На ваше усмотрение настроит:
- - Создаст пользователя для подключения, запретив вход от рута, добавит ему ключ для SSH и запретит вход по паролю. Вместе с этим шагом настраивается iptables (IPv4 и IPv6), запрещая все подключения, кроме SSH, 80 и 443.
- - Настроит WARP для ру-сайтов (попутно прячет выходной IP от типовых «what-is-my-ip» зондов — см. «Защита от деанона» ниже).
- - Включит split-IP: приём Reality на скрытом IP, выход через другой (нужен 2-й IPv4). Полностью разрывает связку входной=выходной IP — см. «Защита от деанона» ниже.

```bash
bash <(wget -qO- https://raw.githubusercontent.com/Jackardios/xray-vps-setup/refs/heads/main/vps-setup.sh)
```

## Почему не <strike>nginx</strike>caddy, haproxy, 3x-ui, x-ui, sing-box...

<strike>Caddy</strike> Angie сам получит сертификаты, поэтому нам не придется их получать через `acme.sh` или `certbot`.  
3X-ui мерзотная панель.  
Sing-box не очень.  
gRPC — основной транспорт; XHTTP/CDN-fronting, возможно, позже.

## Обход DPI и выбор сервера

По материалам разбора «сибирского» DPI (июнь 2026). Блокировка по VLESS/Reality срабатывает только при **одновременном** совпадении трёх сигналов (логика И), поэтому достаточно разорвать **любой** из них:

1. **Подсеть/ASN сервера** (Сигнал 1). Избегайте провайдеров, чьи диапазоны исторически режут: **Selectel, Yandex.Cloud, Hetzner, DigitalOcean, OVH**. Скрипт на установке сам предупредит, если ваш хостинг похож на один из них. Подсеть стоит проверить через [dpi-checkers](https://github.com/hyperion-cs/dpi-checkers) до того, как полагаться на сервер.
2. **TLS-фингерпринт** (Сигнал 2). Все клиентские конфиги и ссылка используют `fp=firefox` — это «лояльный» отпечаток, который и разрывает И-цепочку. **Не меняйте его** на `chrome`/`safari`/`randomized`. И **не меняйте фингерпринт под деградацией**: смена «на лету» эскалирует блок со 120 до 600 секунд на все TLS-соединения к узлу. Лояльный отпечаток должен стоять заранее.
3. **Поведение** (Сигнал 3). >3 параллельных коннектов с интервалом <350–400 мс к одному SNI за 60 с; счётчик ведётся **per-SNI**. Основной транспорт **gRPC закрывает это в корне**: все потоки мультиплексируются в один HTTP/2-коннект (один хендшейк, до ~100 streams) — всплеска параллельных хендшейков просто нет. Дополнительно установщик распределяет трафик по **пулу SNI**: при установке можно добавить до 4 дополнительных имён (поддомены вашего домена или отдельные домены), и каждое имя привязывается к **одному** транспорту (gRPC по умолчанию или Vision — так требует SNI-роутер). Каждое имя становится отдельным Reality `serverName`, vhost Angie со **своим** сертификатом, маршрутом в SNI-роутере и host-записью Marzban — в подписке каждого пользователя оказывается несколько конфигов с разными SNI. Каждое доп. имя должно иметь A-запись на сервер (иначе ACME не выпустит его сертификат). Отдельные регистрируемые домены дают и развязку в CT-логах (и получают собственную decoy-страницу), поддомены одного домена связываемы по eTLD+1. Вторичный Vision несовместим с mux, поэтому для него всплеск размазывается только пулом SNI — потому он и вторичный. Сигнал 1 (подсеть) этим не лечится — полное решение по подсети это CDN-fronting.

## Защита от деанона: split-IP и localhost-утечка

По материалам [гайда zapret](https://publish.obsidian.md/zapret/Privacy/VLESS-localhost-protection-guide) и [разбора детекта туннеля](https://publish.obsidian.md/zapret/Privacy/tunnel-detection-fix-split-ip).

### Угроза

VPN-клиенты (v2rayNG, Hiddify, NekoBox и т.п.) поднимают на устройстве **локальный SOCKS-прокси без пароля** (обычно `127.0.0.1:10808`). Любое приложение-сосед (Яндекс, WB, Ozon, MAX, гос.приложения) может за секунды найти этот прокси, подключиться без авторизации, прогнать через него свой трафик и **узнать выходной IP вашего сервера**. Дальше IP уходит в РКН и сервер блокируется.

Усилитель: если **входной IP (на котором слушает Reality) совпадает с выходным IP**, то утёкший выходной IP — это и есть точка входа. РКН коррелирует его с netflow провайдера (`два IP в одно время от одного NAT → один из них туннель`) и блокирует сервер, попутно вычисляя пользователя.

### Split-IP (полное решение, нужен 2-й IPv4)

В установщике есть режим **split-IP**: Reality слушает только на скрытом входном (ingress) IP, а трафик выходит через другой, видимый (egress) IP — утёкший выходной IP никогда не равен точке входа. Включается при установке (нужен второй IPv4, уже привязанный провайдером к серверу):

- A-запись домена должна указывать на **ingress IP** (туда подключаются клиенты и ACME);
- SNI-роутер Angie слушает 443 на **ingress IP** (xray-инбаунды — на localhost), а `sendThrough` у `direct`-аутбаунда привязан к egress;
- iptables: на ingress открыты только 80/443, SSH — только на egress (поэтому split-IP имеет смысл включать вместе с настройкой SSH-пользователя/файрвола).

Рекомендуется доделать вручную (необязательно, но усиливает защиту трафика самого сервера):

- сделать egress IP системным дефолтом — egress-адрес должен идти **первым**. Пример для systemd-networkd:

```ini
[Network]
Address=EGRESS_IP/24   # первым → системный дефолт
Address=INGRESS_IP/24
Gateway=...
```

- ходить по SSH через egress IP;
- убрать AAAA-запись домена (split — только IPv4; иначе остаётся IPv6-путь для корреляции).

Для marzban-node конфиг xray задаётся панелью — `listen`/`sendThrough` правьте на стороне панели; локальный iptables всё равно применяется.

### Если IP только один

Полностью спрятать выходной IP без второго IP можно лишь прогнав **весь** трафик через WARP/Tor — это медленно (лишний прокси-хоп на каждое соединение), поэтому такого режима в скрипте **нет намеренно**. Вместо этого при включённом WARP («WARP для ру-сайтов») через WARP заодно уходят известные сервисы определения IP (`api.ipify.org`, `ifconfig.me`, `ipinfo.io`, `ip-api.com`, `ip.sb`, …): типовой зонд из соседнего приложения увидит IP Cloudflare, а не сервера, и тормозит при этом только сам этот запрос. Закрывает массовый сценарий, но не гарантия — свой кастомный «what-is-my-ip» это обойдёт. Полная защита — split-IP / второй IP.

### Закрыть утечку на клиенте

- Включите **авторизацию на локальном SOCKS** (логин+пароль), `udp:false`. Для standalone-xray установщик печатает готовый «hardened» клиентский конфиг с уже настроенным SOCKS-паролем.
- Клиенты с поддержкой auth: **Husi**, SFA, saeeddev94/xray; Clash/mihomo в режиме TUN-only безопасен по умолчанию.
- **Не используйте Happ** — он отдаёт xray API на localhost без пароля (один скомпрометированный юзер = дамп/правка конфигов). В marzban-режиме установщик умеет опционально блокировать Happ по User-Agent на подписке.
- sing-box должен быть **≥ 1.4.5** (CVE-2023-43644 — обход SOCKS-аутентификации).
- Проверить своё устройство: [per-app-split-bypass-poc](https://github.com/runetfreedom/per-app-split-bypass-poc) — при включённой auth должно показать «VPN not found».

### Прочее

- xray API (`HandlerService` и т.п.) наружу нигде не торчит: в standalone его нет вообще, у marzban он только на localhost.
- Остаточные риски без технического решения: бан подсети (берите ingress и egress из **разных** диапазонов), бан Cloudflare ASN13335, детект по объёму (постоянный толстый поток на один IP).
